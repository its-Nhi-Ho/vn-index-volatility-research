# VN-Index Volatility Research

This project explores historical VN-Index data and evaluates models that
forecast short-horizon volatility. It is an educational research project,
not investment advice or a trading system.

## Research objective

At the end of trading day *t*, forecast the standard deviation of
VN-Index log returns over the next five trading sessions
(*t*+1 through *t*+5). The target is daily volatility and is **not
annualized**.

The forecasting notebook compares rolling/EWMA statistical baselines
with Ridge Regression and Random Forest. It uses chronological
train/validation/test splits, tunes model hyperparameters on validation
data, and reports test metrics including MAE, RMSE, and out-of-sample
R². A five-window expanding walk-forward evaluation is also included.

## Data

Place the historical data file at `data/vnindex.csv`. The loader accepts
the English column names `date`, `close`, `open`, `high`, `low`, `volume`,
and `pct_change`, as well as the original Vietnamese column names used
in Investing.com exports. See [`data/README.md`](data/README.md) for
details.

The loader parses numeric values, removes invalid or duplicate dates,
sorts observations by date, and drops rows with missing Close values.
Volume is not used by the current forecasting models.

The forecasting notebook checks whether Close falls outside the
High--Low range. It reports any such observations and **keeps them
unchanged**; it does not automatically repair or exclude them. Verify
anomalies against the original data source before deciding how to handle
them.

Do not commit the source CSV. The repository's `.gitignore` excludes
`data/*.csv`.

## Setup (Windows PowerShell)

From the project root:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Open the project root in VS Code, select the `.venv` Python interpreter
as the notebook kernel, and open the notebooks under `notebooks/`.
Alternatively, start Jupyter from the project root:

```powershell
python -m jupyter lab
```

Run each notebook's cells in order. The notebooks locate the project root
by searching for `src/data.py` and expect the project folder structure
to remain intact.

## Notebook workflow

1. Run `notebooks/01_eda.ipynb` to inspect the data, returns,
   distributions, volatility patterns, and data-quality issues.
2. Run `notebooks/02_volatility_forecasting.ipynb` to build the
   five-session volatility target and features, evaluate statistical
   baselines, tune Ridge and Random Forest on the validation period, and
   assess performance on the test period.
3. The forecasting notebook also evaluates five consecutive windows
   within the test period. It refits models on expanding historical
   data, keeps the validation-selected hyperparameters fixed, and
   excludes observations whose forward targets are not yet available at
   each window's start.

The forecasting configuration, including the horizon and split
settings, is near the top of `02_volatility_forecasting.ipynb`.
Generated figures and result CSVs are written under `reports/`.

## Reproducibility and interpretation

- The test period is chronological and should not be used to select new
  features or hyperparameters.
- The five walk-forward windows are consecutive portions of the same
  test period, not five independent samples.
- Forecast accuracy does not establish a causal relationship or imply
  trading profitability.
- Results can change if the source data, split configuration,
  dependencies, or model settings change.
